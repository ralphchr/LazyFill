# Implementation status — 0.2.2

Implemented: compact five-field profile including contact number, common English question matching, dot defaults for unrelated text, zero defaults for number-only fields, alphanumeric placeholders for supported rules, length/case handling for common patterns, numeric Google metadata parsing, phone formatting normalization, randomized choices and supported grid rows, native dates and recognized birthday components, blank PNG/PDF/TXT generation, accepted-type checks and automatic attachment on normal file inputs, blank downloads for manual pickers, automatic Next navigation, resume across full document loads, popup-independent progress, Stop/Continue controls, loop detection, inactivity expiry, and final-page detection without submission. Existing answer preservation, conservative clearing, temporary-answer tracking, and section outlines remain available.

Google uploads: the same-origin `docs.google.com/picker?hostId=file-upload` path is now handled. The extension opens the question’s picker, checks accepted MIME types and size limits, uses a native file input or the Browse upload drop zone, optionally confirms Select, and waits for the generated filename in the form plus picker closure. Upload progress, rejection, cancellation, unconfirmed attempts, and conservative clearing are tracked. Instruction/template links are not counted as uploads. No additional host or iframe permissions are requested.

Manual: inaccessible or unrecognized picker variants, unsupported file types, time fields, unrecognized date/grid controls, and form-specific validation. A run pauses when the form refuses to advance; the user resolves the issue and continues. Automatic mode follows one conditional route from the current page.

Limitations: Google's DOM and embedded schema are undocumented. Outlines list available sections rather than predicting conditional routing. Automatic navigation requires tab session storage. Radio/dropdown resets depend on available form controls. Clearing local file inputs does not delete cloud uploads. Submission protection is a best-effort reminder for recognized submit actions, not a universal interception mechanism.

Automated validation: DOM regressions cover profile matching, random option selection, valid blank file contents, accepted-type checks, attachment events and preservation, date components, grids, multi-section navigation, reload resume, Stop, validation/upload pauses, loops, timeouts, and submission exclusion. Picker-frame tests cover input transfer, drop transfer, Select, confirmation, rejection, cancellation, pending reset, clearing, and stable question identity. A production-bundle smoke test exercises popup messaging, page filling/clearing, outlines, automation after popup closure, and a simulated picker upload. The actual picker URL and accessible controls were inspected read-only in Edge; no live Google upload was performed. These fixtures do not replace testing against the live upload service.
