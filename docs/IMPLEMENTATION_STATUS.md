# Implementation status — 0.2.0

Implemented: compact four-field profile, common English question matching, dot defaults for unrelated text, randomized choices and supported grid rows, native dates and recognized birthday components, blank PNG/PDF/TXT generation, accepted-type checks and automatic attachment on normal file inputs, blank downloads for manual pickers, automatic Next navigation, resume across full document loads, popup-independent progress, Stop/Continue controls, loop detection, inactivity expiry, and final-page detection without submission. Existing answer preservation, conservative clearing, temporary-answer tracking, and section outlines remain available.

Manual: Google upload pickers or file inputs that cannot accept generated files, unsupported file types, time fields, unrecognized date/grid controls, and form-specific validation. A run pauses when the form refuses to advance; the user resolves the issue and continues. Automatic mode follows one conditional route from the current page.

Limitations: Google's DOM and embedded schema are undocumented. Outlines list available sections rather than predicting conditional routing. Automatic navigation requires tab session storage. Radio/dropdown resets depend on available form controls. Clearing local file inputs does not delete cloud uploads. Submission protection is a best-effort reminder for recognized submit actions, not a universal interception mechanism.

Automated validation: DOM regressions cover profile matching, random option selection, valid blank file contents, accepted-type checks, attachment events and preservation, date components, grids, multi-section navigation, reload resume, Stop, validation/upload pauses, loops, timeouts, and submission exclusion. A production-bundle smoke test exercises popup messaging, page filling/clearing, outlines, and automation after the popup closes. These fixtures do not replace testing against a real Google Form and its upload picker in Edge or Chrome.
